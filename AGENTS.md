# Development instructions

## Mission and compatibility

Maintain this independent continuation of TheKeyMachine (TKM), Rodrigo Torres's Maya animation toolset. The priority is Maya 2027 on Windows 11 and modern macOS, including the requested macOS Tahoe 26.6.2 target and newer releases. These are development targets, not claims of verified compatibility or Autodesk certification.

- The README and `how_to_install.txt` describe the upstream Maya 2022–2025 release. Do not treat them as evidence that this fork works on Maya 2027.
- Autodesk's [platform alignment table](https://aps.autodesk.com/developer/overview/me-vfx-platform-alignment) lists Maya 2027 with Python 3.13.3 and Qt/PySide 6.8.3. Confirm the installed Maya update's actual versions before choosing APIs or changing version gates.
- Use Maya's bundled Python, PySide6, and matching shiboken6. Do not pip-install replacement Qt bindings into Maya. Preserve existing older-Maya/Linux paths when practical; do not expand their support matrix without a task requiring it.
- Preserve GPL-3.0 licensing and original author attribution. Describe the fork as independently maintained; do not imply upstream endorsement.

## Working rules

- Read the affected flow and search all callers before editing. Fix the shared cause; reuse existing helpers before adding dependencies or abstractions.
- Keep diffs focused. Match surrounding style and preserve existing line endings; many source files use CRLF. Avoid whole-file formatting during compatibility fixes.
- Preserve unrelated working-tree changes. Do not commit generated bytecode, personal Maya preferences, user data, or `.context/` artifacts.
- Keep this file concise and current. Put feature documentation in the README or dedicated docs; add nested instructions only when a subtree needs different rules.

## Maya and Qt constraints

- Audit both installer and runtime imports when changing Qt compatibility; their fallback order currently differs. PySide and Shiboken must come from the same Qt generation.
- Follow Autodesk's [Qt 6 migration guidance](https://help.autodesk.com/cloudhelp/2026/ENU/Maya-DEVHELP/files/Whats-New-Whats-Changed/2025-Whats-New-in-API/Qt6Migration.html). Check removed desktop APIs, enum behavior, and high-DPI scaling instead of assuming an import change completes the port.
- Reuse Maya's QApplication and parent windows to Maya. Keep Maya commands and widget operations on the main thread; use Maya's deferred execution for work returning from background threads.
- Make toolbar reload/close clean up owned timers, callbacks, and scriptJobs. Do not kill callbacks belonging to other tools.
- Preserve undo/redo for animation edits. Close undo chunks and restore temporary state in `finally` blocks. Exercise empty selections, missing nodes, and locked/referenced attributes for affected operations.
- Treat imports as potentially mutating: `toolbar.py` creates user files and instantiates `tb` at module scope. Do not import UI modules as a generic headless smoke test.

## Paths, installation, and user data

- Resolve Maya user locations through `cmds.internalVar` and existing config/path helpers. Use `os.path` or `pathlib`; account for spaces, non-ASCII usernames, and platform path-list separators.
- Keep installed code separate from `TheKeyMachine_user_data`. Preserve custom scripts, preferences, selection sets, and saved animation data during upgrades and uninstall work.
- Respect `INSTALL_PATH`, `USER_FOLDER_PATH`, and studio settings. Do not assume the code directory is writable.
- Installer changes must tolerate repeat execution without duplicate TKM entries and preserve unrelated `Maya.env` content. Test install/uninstall using disposable Maya preferences, never a user's working setup.
- The upstream README announces the website shutdown. Do not introduce startup or core-animation dependencies on upstream registration, update, or reporting services. Fail gracefully when optional services are unavailable.

## Development and verification

There is currently no declared dependency installer, build system, automated test suite, or CI configuration. Do not invent commands for them. Maya supplies the host dependencies.

For development, launch a fresh Maya with disposable preferences and the repository root on `PYTHONPATH`. Configure `INSTALL_PATH` to that root and `USER_FOLDER_PATH` to a disposable directory on Maya's Python path: the toolbar resolves Connect templates through the former and imports generated user modules through the latter. Keep these machine-specific config changes out of commits. Alternatively, test the drag-and-drop installer in that disposable profile; it copies files, so rerun against current source when validating changes.

In Maya's Python Script Editor, start the toolbar with:

```python
import TheKeyMachine.core.toolbar as toolbar
toolbar.tb.startUI()
```

Confirm `toolbar.__file__` points at the intended development or installed copy. Use a fresh Maya session for final checks because module reloads can retain state.

- For Python edits, run this syntax-only check from the repository root with Maya 2027's `mayapy` executable (quote its full path if needed):

  ```sh
  mayapy -c "import ast, pathlib; files = [pathlib.Path('TheKeyMachine_Drag&Drop_installer.py'), *pathlib.Path('TheKeyMachine').rglob('*.py')]; [ast.parse(p.read_bytes(), filename=str(p)) for p in files]; print('Parsed', len(files), 'Python files')"
  ```

  This does not import modules or write bytecode. A system Python fallback checks only that interpreter's syntax; it does not establish Maya compatibility.

- For nontrivial logic changes, leave one focused runnable regression check covering the failure. Prefer standard-library checks for pure logic; use `mayapy` with `maya.standalone` for scene operations that support it. UI behavior requires interactive Maya.
- Do not add tests that merely mirror reversible, low-impact edits. Run checks appropriate to the change; broaden them only when failures or unresolved risks warrant it.
- For UI/compatibility changes, verify launch, close/reopen, reload without duplicate UI/callbacks, icons, menus, and scaling in Maya. For animation changes, exercise the affected tool on a disposable keyed scene and check undo/redo and selection behavior.
- Before claiming platform support, test installation, restart, toolbar/graph editor, representative key editing, selection persistence, and uninstall on both Windows 11 and the requested macOS target. Record exact OS, CPU architecture, Maya update, Python, and Qt versions. Mark unavailable environments as untested.
- Run `git diff --check` before handing off. Report what changed, checks actually run, and remaining platform gaps; syntax success alone is not a successful Maya port.
